# GMGame 场景交付、合并与验收入口

## 独立安装版：先定位，再执行

本技能安装在个人技能目录，供 GMGame 使用。可以从 `small-game-puzzle` 仓库根、`GMGame/GMGameProject` 或其子目录启动 Codex；不把当前工作目录直接当成 Unity 项目。

1. 以当前加载的本 `SKILL.md` 所在目录作为 `<SKILL>` / `$skillRoot`。运行 `python -B -X utf8 "<SKILL>/scripts/project_locator.py" --workspace "<当前 Codex 工作目录>"`，只读取得 `<REPO>`、`<PROJECT>`、当前分支和提交。定位失败先说明原因，不猜绝对路径。目录名不绑定维护者盘符或用户名。
2. 所有 `handoff.py --project` 参数使用定位后的 `<PROJECT>`；工具入口始终为 `<SKILL>/scripts/handoff.py`，计时为 `<SKILL>/scripts/handoff_timing.py`。不得改用目标分支中 `.agents/skills` 的旧脚本。包内 Markdown 相对本文件解析；文档中的 `Assets/`、`Docs/` 是 `<PROJECT>` 下的业务输入/输出，不能写到技能安装目录。
3. 使用本包 `references/` 内的合并、同步与验证流程。目标项目的 `AGENTS.md`、项目指南和文件更新标准仍约束业务修改；仓库链接到同名旧技能时，不把链接误当成更换当前已选技能版本的指令。用户显式要求使用某个旧路径/版本时遵从并说明版本。业务规则有实际冲突时先解释并澄清，不静默套用旧合并流程。
4. 保持整轮技能版本一致。分支切换、sync 和 deliver 均不覆盖、同步或更新个人技能目录。安装包、个人设置、技能备份不加入游戏交付提交。需要升级时在当前合并结束后另行安装；项目内的旧技能源文件作为正常 Git 文件合并，不把它们当作当前执行工具。
5. 合并前检查 Git、Python 3.11+、匹配项目版本的已打开 Unity 和 Unity MCP；MCP 实例路径必须等于 `<PROJECT>`。安装成功仅说明文件与发现配置就绪，不代表 Unity 或合并运行验证通过。保留原流程的检查点、场景范围、冲突、验证和推送约束。

个人目录安装和同名旧版停用见 [安装说明](INSTALL.md)。安装或升级本包只处理技能及个人配置，不执行真实项目合并、提交或推送。


使用本技能时，先阅读并遵守 [项目指南](references/ProjectGuide.md) 的“工作原则与项目基线”，然后读取 [完整工作流程](references/Workflow.md)。按任务涉及的业务补读指南章节，复用本轮已加载内容。按流程中的执行路由读取对应参考文件。

本分发包的 references 是发布时的流程快照；维护源在仓库 Docs，执行本版本时使用包内流程。

需要在项目外安装、从仓库根目录使用或向同事分发 `.skill` 时，按 [独立安装与分发](INSTALL.md) 构建及安装；分发版携带流程快照和脚本，安装不执行场景合并。

场景采用定向写入：sync 只更新当前作者的个人场景，deliver 只更新目标对应的基础场景；其余场景保留接收分支合入前状态。代码和公共资源正常合并。重复及交替操作依据双方历史快照与有效同步记录，不以当前分支基础场景或 Git 已合并状态替代场景基准。

两个合并入口均复用原项目及已打开的 Unity：停止播放、保存有效修改、提交需要保留的开发内容，再执行合并。验证通过并创建本地结果提交后，自动推送目标分支：sync 推送当前开发分支，deliver 推送 develop_base；用户明确要求不推送或等待时优先遵从。不关闭、重启或另开 Unity，不创建 worktree、项目副本或 develop_base_merge_* 分支。只更新技能时不执行真实合并、提交或推送。

场景发现与重复合并依据见 [场景配对与同步记录](references/scene-sync.md)；当前 Editor 验证及结果汇总见 [验证工具](references/automation-tools.md)。使用随技能维护的工具，不复制历史交付专用脚本。

合并写入前完成来源快照与场景输入核对；测试收尾同时核对设置的内存值和磁盘值，再生成最终汇总。Unity Reload 弹窗按执行流程交由用户处理，确认实际恢复后从原阶段续跑，不重做已有有效步骤。

执行时使用 [执行辅助工具与续跑](references/execution-tools.md) 的场景保护核对、阶段记录、恢复差异清单及 project/repository 清单入口，减少临时脚本。工具失败先停止依赖步骤，处理具体原因；既有场景语义裁决、输入校验和必要验证保持不变。

验证失败后，按 [失败后的定向诊断](references/automation-tools.md#失败后的定向诊断) 先归并失败原因、验证修复，再运行最终必要覆盖；单例偶然通过不能触发盲目全量重跑。原始证据完整保存，对话只输出摘要；恢复、报告与哈希核对按执行流程集中收尾，不重复已有有效步骤。

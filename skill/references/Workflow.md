# GMGame 场景双向合并与验收

用中文执行，先遵守已加载的 [项目指南](ProjectGuide.md)。本技能供所有同事使用，不依赖维护者机器、用户名或历史聊天。常用流程为每轮从最新 develop_base 创建开发分支并复制个人场景；同一开发分支也支持多次同步、多次交付及交替双向合并。

## 两个操作

| 用户表达 | 执行位置与结果 |
|---|---|
| “将 develop_base 合并到当前分支” | 原目录保留当前开发分支，合并远程最新代码和资源；主分支基础场景增量三方合入当前作者个人场景，当前分支基础场景保持不变 |
| “将当前分支合并到 develop_base” | 保存并提交开发内容，在原目录切换本地 develop_base、同步远程最新版本，再合入固定开发提交；场景增量只写对应基础场景，目标已有个人场景保持不变，不引入源分支个人副本；完成后停留 develop_base |

不先将 develop_base 合入个人分支再反向交付；源分支是否已同步由实际历史判断。主程指定他人的开发分支时，以指定源分支识别作者，不用主程 Git user.name。方向不明确时只询问方向，不默认创建验证分支。用户指定创建新开发分支是单独请求，不是本技能合并的隐含步骤。

## 统一边界

- 场景写入范围按 [执行流程](merge-workflow.md) 单独控制，包括 `.unity` 和配套 `.meta`；仅指定方向的目标场景可写，其余场景相对接收分支合入前保持不变。deliver 的比较起点是本地 develop_base 已完成远程对齐后的版本；正常远程对齐的更新不属于开发场景交付。新增、删除、移动及无配对场景先明确目标身份，不能退回普通 Git 自动合场景。

- 两个操作都复用原项目及 Library，不创建 worktree、项目副本、develop_base_merge_* 分支，不删除历史隔离区。目标被其他工作区占用时说明具体位置，不强制切换或另建隔离区绕过。
- Unity 播放中先识别需保留的运行时调整，再停止 Play Mode，保存有效编辑状态。保持 Editor 打开，不关闭、重启、另开实例或强杀进程。无法可靠保存、控制刷新或重载场景时停止相关写入，完成可独立进行的只读分析并说明阻碍。
- 明确要求合并即授权本流程中的有效开发改动检查点提交、相关冲突修复、场景迁移、必要验证及本地结果提交。先检查具体文件，不盲目 git add -A，不夹带无关工作、临时文件、运行时材质写回或明确排除项；归属不明时询问。仍有会影响切分支/合并的未处理改动时不继续，不自动 stash/reset/clean。
- 两个合并操作默认包含验证、本地结果提交和自动推送，无需用户另行要求推送：develop_base → 当前分支时推送当前开发分支；当前分支 → develop_base 时推送 develop_base。仅推送本次目标分支，不顺带推送源分支、不强推。检查点无需远程备份才能合并；远程选择与 SHA 核验按执行流程处理。
- “先看差异”“先不提交”“只提交不推送”“人工验证后再提交/推送”等当轮要求优先；不能把已合并、已本地提交、已推送、人工通过混为一谈。测试失败或不可裁决冲突保留现场及原始证据，不伪报通过。

## 按需读取

- 执行两个合并操作：读 [执行流程](merge-workflow.md) 和 [场景配对与同步记录](scene-sync.md)。使用标准命令时按需读取 [执行辅助工具与续跑](execution-tools.md) 对应段落；运行验证时再读 [验证工具](automation-tools.md)。
- 仅整理清单或检查遗漏：读 [清单与只读验收](handoff-and-audit.md)，不触发保存、业务提交或切分支。
- 仅维护技能：只修改技能、工具及相关文档并验证，不执行真实合并、测试游戏、提交或推送。复用已读规则，不因下一个文件而重读全部文档。

## 完成与续跑

固定开发分支、作者、源提交、远程基线、本地目标起点、实际项目路径和每对场景依据。同一任务续跑核对已有阶段与实际字节，继续未完成步骤，不重复提交或重跑相同有效验证。相同环境错误且条件未变时停止试错。

证据保存在 Docs/SceneHandoffs 的本轮目录，路径相对项目、时间带时区；历史证据不重写。合并报告和机器记录即可表达同一结果，不为普通合并另外生成多份重复清单。全部结果来自固定源版本及目标实际输入。

最终说明方向、当前停留分支、结果提交、推送状态、验证摘要、人工待验项和报告位置。没有新变化时说明已对齐，不制造空提交。当前原工作区应保留目标分支，不执行旧隔离流程的 detach/分支释放步骤。

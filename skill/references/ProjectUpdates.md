# GMGame 项目文件更新标准

本标准规定文件新增、修改、移动、重命名、替换和删除的执行要求，由 `gm-project-update` skill 加载。适用于 Unity 项目 `GMGame/GMGameProject/`、仓库 `Sources/` 及相关 Agent 入口；具体玩法约束见 [项目指南](ProjectGuide.md)。

本文是更新流程、目录选择和验收要求的维护正文；Agent 和 skill 入口仅引用本文。用户明确指定的任务范围和目录优先，存在必要例外时说明原因和实际落点，不另建一份冲突标准。

## 1. 确定更新范围

开始修改前确认：要实现的行为、文件类型、所属章节或公共系统、已有模块与引用位置。遵守当前工具已加载的仓库入口；尚未加载时读取对应的根目录 `AGENTS.md` 或 `CLAUDE.md`。检查相关代码、资源及 Git 暂存／未暂存状态；涉及 C# 或程序集时检查最近的 `.asmdef`。修改现有文件前识别用户已有改动，不覆盖、重置或顺手清理无关内容。

规则按任务加载：先读范围、操作和验证要求，按文件类型补读目录及命名规范，按业务影响补读项目指南。已加载且仍在上下文中的内容直接复用；仅在规则变化或相关内容缺失时补读必要部分，不沿相互引用重复读取入口、技能和标准。后续仅解释代码、说明复现步骤或汇报状态时，沿用相关规则，不重新启动文件更新流程。

- **现有模块的修复和扩展**：保留程序集和必要配置；文件及资源的章节落点遵守第 2 节，未匹配场景前缀且不涉及归属调整的既有模块继续原位维护。C# 文件头与命名空间遵守下方统一规范，不因局部更新自动搬迁整个无关模块。
- **新增独立模块或独立资源**：按下方类型和章节目录落盘，不散落到 `Assets/` 或各资源类型根目录。
- **明确要求整理目录**：在任务范围内归类迁移，并同步引用；不要扩大为其他章节或全项目重构。
- **仅分析或评审**：按本标准检查和提出可执行结论，不自动执行文件变更。

一般目录选择和引用修复可在已授权任务内直接完成；仅在缺失信息会改变功能、归属或无法保护现有修改时澄清。创建或更新文件本身不要求增加审批步骤。

## 2. 章节归属

章节归属按场景名称前缀中的编号一一对应。`TestScene_all_001`、`GMGameScene_001` 属于 `Chapter_01`，依次类推；场景编号使用三位数字，章节目录使用 `Chapter_` 加至少两位的同一编号，例如 `010` 对应 `Chapter_10`。需要按章节分目录的文件类型，按实际内容创建章节目录；`GMScenes` 中的场景文件采用第 3 节的固定两层目录，章节编号仅表示归属，不增加目录层级。

| 测试场景／文件名前缀 | 正式场景／文件名前缀 | 章节归属 |
| --- | --- | --- |
| `TestScene_all_001` | `GMGameScene_001` | `Chapter_01` |
| `TestScene_all_002` | `GMGameScene_002` | `Chapter_02` |
| `TestScene_all_003` | `GMGameScene_003` | `Chapter_03` |
| `TestScene_all_004` | `GMGameScene_004` | `Chapter_04` |
| `TestScene_all_005` | `GMGameScene_005` | `Chapter_05` |
| `TestScene_all_006` | `GMGameScene_006` | `Chapter_06` |

- 按区分大小写的前缀匹配，包含精确同名和其后的任意后缀。例如 `TestScene_all_004_yuhc`、`GMGameScene_004_variant` 及以这些前缀命名的文件、资源均属于第四章，实际目录按第 3 节的文件类型规则选择。
- 以这些前缀命名的脚本、Prefab、模型、材质、Shader、动画、贴图、音频、配置、测试及源工程，必须放入各自文件类型根目录下对应的 `Chapter_XX`，具体结构见第 3 节；不集中混放到单一 Chapter 根目录。场景文件直接放入 `GMScenes` 下的类型目录，不创建 `Chapter_XX` 子目录。
- 未以前缀命名但专用于某个匹配场景的功能与资源，也按该场景编号归属；场景前缀是明确的归属依据，不能因为全局管理器引用、当前打开的场景或旧章节选择卡片映射而改归其他章。游戏场景 004、005 的专属内容分别归第四、第五章，不再统一归第三章。
- 无上述章节前缀且真实跨章节共用的资源、全局系统归 `Common`，保留一份；已有明确章节前缀的文件仍按前缀归属，不因被其他章节引用而自动改归公共目录。
- 本规则用于新增、维护和明确目录整理任务。仅增加规则不触发全仓库历史文件搬迁；实际迁移任务覆盖的文件必须按此规则归类，并按第 4–6 节同步 `.meta`、引用和验证。尚未迁移的旧路径清单是当前布局记录，不能作为新增内容继续使用旧归属的依据。

登录资源按全局入口归 `Common`。章节选择卡片、存档缩略图等多章 UI 资源按公共 UI 管理。某章专用道具即使被全局 Player 预览引用，仍属于该章。共享资源保留一份；不要仅因“以后可能复用”提前复制或抽到公共目录。

## 3. 文件类型与落点

下表 `Assets/`、`Docs/` 相对 Unity 项目根；`Sources/` 相对 Git 仓库根。`<归属>` 表示按第 2 节编号确定的 `Chapter_XX` 或 `Common`，`<功能>` 表示实际模块／房间／效果名称。表中模板是新增及归类迁移内容的规则，不表示所有目录已存在；需要时创建，不批量生成空目录。

| 类型 | 新增独立内容的目录 | 维护要求 |
| --- | --- | --- |
| 运行时代码 | `Assets/GMScripts/<归属>/<功能>/` | 章节专用代码按第 2 节归类；公共现有系统继续维护 `Save/`、`CombinationItems/Player/`、`Inventory/`、`UI/` 等模块。目录变化不自动修改命名空间。 |
| 正式／测试场景 | `Assets/GMScenes/Game/`、`Assets/GMScenes/Test/` | `.unity` 文件直接放在对应类型目录，保持 `GMScenes/<类型>/` 两层目录，不创建 `Chapter_XX` 文件夹；迁移保留场景名和 GUID，同步 Build Settings、场景路径消费者及测试。 |
| Editor 工具 | `Assets/Editor/<归属>/<功能>/` | 仅在 Editor 使用；已有工具及模块自带 `Editor/` 目录可继续维护，不将 UnityEditor 依赖带入 Player 程序集。 |
| 自动化测试 | `Assets/Tests/EditMode/<归属>/<功能>/` 或 `PlayMode/<归属>/<功能>/` | 先检查最近 `.asmdef`；若属于现有专用测试程序集，在该程序集根内分章，或沿用其已有模块目录。不能为了目录统一改变测试程序集或丢失依赖。 |
| Prefab、直接引用的模型包 | `Assets/GMPrefabs/<归属>/Props/<模型或机关>/`，效果用 `VFX/<功能>/` | FBX、网格、配套材质、必要贴图及 Prefab 整包管理。场景环境沿用章节内既有 `Environment/` 或 `环境/`、房间目录。全局 Prefab 用 `Common/Global/`。 |
| 独立材质 | `Assets/GMMaterials/<归属>/<功能>/` | 模型包私有材质留在模型包内；动态加载材质可随运行资源放在 Resources 专题目录，避免同一材质重复保存。 |
| 独立 Shader、include | `Assets/GMShaders/<归属>/<功能>/` | 既有模型／特效包内的 Shader 继续随包维护。新增独立 Shader 优先使用 GMShaders，保留运行查找所用 Shader 声明名。 |
| 动画、AnimatorController | `Assets/GMAnimations/<归属>/<功能>/` | 既有 `FadeAni/`、`ScaleAni/` 继续原位维护；新增独立动画按归属存放，检查控制器、Clip 和事件函数引用。 |
| 动态加载模型／机关／效果包 | `Assets/Resources/<归属>/<功能>/` | 只有需要运行时按地址加载、或已按此方案维护的资源包使用 Resources；直接引用的独立模型按 GMPrefabs 管理。 |
| Resources 纹理、音频、视频 | `Assets/Resources/<归属>/Pictures/<功能>/`、`Audio/<功能>/`、`Video/` | 模型包私有贴图可以留在包中；复用现有更细分类，如 `Audio/SFX/`、`Audio/BGM/`。RenderTexture 用同归属的 `RenderTexture/`。 |
| JSON 配置 | `Assets/Resources/<归属>/Config/<功能>/` | 配置读取、Editor 写入、默认值和版本兼容同步；公共本地化为 `Common/Config/Localization/`，菜单配置为 `Common/Config/UI/`。 |
| Profile、ScriptableObject | `Assets/Resources/<归属>/<功能>/`；后处理用 `Profiles/` | 沿用功能现有约定，如 `BurningProfiles/`；并非所有 `.asset` 都是 JSON 配置，不强制塞入 `Config/`。 |
| 可编辑美术源文件及生成脚本 | `Sources/<归属>/<功能>/` | `.blend`、源工程和生成器与 Unity 导入产物分离；已存在的跨章节源工程可在需要时归 `Sources/Common/`。输出目标仍指向对应 Assets 目录。 |
| 文档、参考与证据 | `Docs/` 的现有用途分类 | 项目规则用 `Project/`，流程用 `Workflows/`，系统用 `Systems/`，机关用 `Puzzles/<功能>/`，美术用 `Art/<功能>/`。现有专题原位更新；跨章节专题的新章节专用子项可用 `Chapter_XX/`，避免另一套平行文档树。 |
| Agent skill | `.agents/skills/<skill-name>/SKILL.md` | 保留发现元数据和执行入口；规范正文放在 Docs 对应专题，可选 UI 元数据放 `agents/openai.yaml`。 |

### 固定位置与既有边界

- `Assets/GMScenes/` 保持 `Login/`、`Chapter/`、`Cutscenes/`、`Game/`、`Test/` 类型分类。以 `Assets/` 为起点，只保留 `GMScenes/<类型>/` 两层目录，场景文件直接放在类型目录内；不在 `GMScenes` 及其类型目录下创建 `Chapter_XX/` 文件夹，也不按章节或作者继续分层。现有 `Chapter/` 是章节选择场景的类型目录，保留该目录。目录归类不自动重排构建索引或修改章节选择卡片映射。
- 第三方包、TMP、`Packages/`、`ProjectSettings/` 保留工具所需结构。`Library/`、`Temp/`、`Logs/`、`obj/`、生成的 `.csproj/.sln` 不作为手工维护源码；不要删除用户或工具的无关状态。
- 不重新创建已淘汰的 `GMTextures`、`GMModels`、`GMEditor`、`GMPostProcess`、`GMResources`、`GMSources`、`GMGameProject/ArtSource` 作为新资源根目录。
- 既有中文目录及专题命名继续沿用；同一专题内保持一种命名方式。新增文件使用稳定的功能名，不以 `new`、`final2`、日期副本代替正式命名。历史证据目录可按日期命名。
- 新 C# 文件名与主要类型一致；既有序列化类型、SaveId、物品标识、Shader 名不随文件整理改名。不要为新目录机械添加 `.asmdef`。

### CSharp 文件头与命名空间

`Assets/` 下所有 `.cs` 文件必须遵守本节，包括运行时代码、Editor 工具、自动化测试及 `partial` 类型的每个文件。今后新增、复制或生成 C# 文件时必须同时满足文件头和命名空间要求；修改、移动或重命名已有文件时保持这些约定。

- 自定义 C# 文件名必须以 `GM` 开头，已有此前缀时不重复添加，例如 `GMPlayerController.cs`。与文件对应的主要类型同步使用 `GM` 前缀，保持 Unity 脚本与类型匹配；`partial` 分文件保留后缀，例如 `GMRewardActivationVisualController.XuanwuContract.cs`。多类型数据文件保留其组织方式，辅助类型、字段、SaveId、资源路径和对象名称不因文件前缀规则自动改名。

文件头必须位于文件最顶部，在 `using`、`#if` 和类型声明之前。以下以 `2026-09-17` 创建的 `GMPostEffectsBase.cs` 为例：

```csharp
// ===============================================
// File:          GMPostEffectsBase.cs
// Company:       Yoozoo Games Co., Ltd.
// Author:        SDK
// Created:       2026-09-17
// Copyright:     © Yoozoo Games Co., Ltd. 2026
// ===============================================

namespace NetherTomb
{
    // 类型定义
}
```

- `File` 填写实际文件名，包含 `.cs` 扩展名；重命名时同步更新，`partial` 文件各自填写自身文件名。
- `Created` 填写该文件创建当天的日期，格式为 `YYYY-MM-DD`；以后修改、移动或重命名时保留创建日期，新建副本使用副本创建日期。示例日期不是所有未来文件的固定值。
- 仅 `File` 和 `Created` 按文件填写；分隔线、字段顺序、对齐空格及 `Company`、`Author`、`Copyright` 与模板保持一致。`Author` 固定为 `SDK`，版权行固定为 `© Yoozoo Games Co., Ltd. 2026`，不自动替换作者或年份。
- 每个文件只保留一份文件头，文件头后空一行。已有同类文件头在原位更新；其中的功能说明注释保留在统一文件头下方。
- 所有类型统一声明在 `namespace NetherTomb` 中；不得省略命名空间，也不按目录、章节、模块或测试用途添加子命名空间。同名类型冲突通过明确的类型命名解决，并同步消费者。
- `.asmdef` 的 `rootNamespace` 及 Editor 项目生成默认命名空间统一为 `NetherTomb`，同时保留实际需要的程序集名称、引用和平台边界。默认命名空间配置不能代替源文件中的显式声明。
- 类型引用、反射类型名、UnityEvent 和相关序列化配置直接使用当前类型名；不为旧命名空间添加 `MovedFrom`、兼容别名或包装类型。涉及类型变更时同步真实引用并验证绑定。

新增或重命名 C# 文件后，完成前逐项核对 `GM` 文件名前缀、对应主要类型、文件头、实际文件名、创建日期、显式命名空间及程序集配置；脚本模板或生成器的输出也必须满足本节要求。

## 4. 各类更新的执行要求

| 操作 | 执行要求 |
| --- | --- |
| 新增 | 先查同功能资源／代码，复用有效内容。确定类型、归属和模块后创建；Unity 生成新的文件及目录 `.meta`，新资源不得复制旧 GUID。补齐实际加载或序列化绑定，不留下没有消费者的重复产物。 |
| 修改 | 在原文件中进行任务需要的改动，保留现有 GUID 和有效参数。运行时临时视觉效果使用实例材质或 MaterialPropertyBlock，避免将临时关键词／颜色写回共享资产。 |
| 移动／重命名 | 记录旧新路径，优先用 AssetDatabase；使用文件系统时资产和 `.meta` 必须成对迁移，防止 Unity 在间隙生成新 GUID。刷新后核对 GUID、子资源 fileID、程序集归属和全部相关引用。 |
| 替换／重新生成 | 只有语义相同、需要维持原对象身份的替换才保留原 GUID；重新导出的 FBX 核查子资源 fileID 和真实源材质名。属于新增或复制的资产使用新 GUID；不要把别的资源的 `.meta` 覆盖过来。 |
| 删除／合并 | 先确认引用和实际使用情况，再删除资产与 `.meta`。合并前确认内容和导入语义相同，更新所有消费者后移除旧项；同名、当前未启用或未出现在一次画面中都不等于可删除。 |

目录整理不同时改动与任务无关的画质映射、光照、反光、HDR、Bloom、Shader 参数或玩法配置。文件改名是路径更新，行为调整需要独立依据和验证。

### 删除与失效引用的判断

检查场景、Prefab、材质、动画、ScriptableObject、构建配置、脚本和生成器，覆盖以下几种引用：

1. `.meta` GUID 及子资源 fileID 的序列化引用。
2. `Resources.Load/LoadAll` 的字面量、拼接前缀、配置地址、反射类型名及 Editor 路径。
3. FBX importer 的 Material／Texture2D `externalObjects`，以及模型中的真实材质标识和场景覆盖。
4. 运行时生成、对象池、背包预览、存档恢复等间接消费者。

失效引用应先判定原因：仍在使用且可确定原资源时恢复或正确重绑；已经删除的模型目标或不再匹配源材质名的映射应清理；已经失效且不使用的可选贴图字段可显式置空。有效墙体缺材质时修复绑定或恢复合理的模型继承值，保持对象原有启用状态。不要仅为了让扫描为零批量清空所有缺失引用。

成批删除／合并留下相对路径、GUID、内容哈希、处理理由和可恢复来源，放入 `Docs/Project/AssetCleanup/` 或对应回归记录；若内容尚未提交，保存可恢复的原文件证据，不能把一次性 `/tmp` 路径作为唯一恢复办法。历史交付和验收证据不得作为普通冗余文件删除。

## 5. 路径与引用同步

- 文档链接相对文档自身位置；业务和配置路径相对其约定根目录。使用 `/`，不写入本机用户名或绝对路径。原始运行日志、历史快照的路径保留证据语义，不能改写为新的当前引用。
- `AssetDatabase` 使用 `Assets/...` 项目相对路径；`Resources.Load` 使用相对 Resources、无扩展名的地址。生成脚本从脚本位置推导仓库或项目根，不依赖启动时的工作目录。
- FBX 和独立材质使用不同的资源地址，避免按类型加载时选中 FBX 内嵌材质；只检查文件是否存在不足以证明加载正确，应核对返回对象身份。例如模型 `Chapter_03/Lvzhuzi/Lvzhuzi` 与材质 `Chapter_03/Lvzhuzi/M_Lvzhuzi`。
- 迁移 Shader 时检查 `Shader.Find`、include、Fallback、材质和 GraphicsSettings；路径变更不要求更改 Shader 声明名。
- C# 移动／类型变更检查 `.asmdef`、命名空间、MonoBehaviour 绑定及 UnityEvent。类型或字段必须改名时处理序列化迁移，不能只修复编译错误。
- 新增／变更场景同步核对 Build Settings、`SceneEnum`、加载分支、初始化器和章节映射。必要时更新对应测试场景；不要整份覆盖测试专用差异或用户未保存修改。
- 更新实际维护文档和工具入口。历史清单中的旧路径、哈希与 Git blob 保留，另加当前映射或后续记录。Resources 归属和当前加载约定同步到 Resources 目录说明（目标项目内 `<PROJECT>/Docs/Project/ResourcesLayout.md`）。

## 6. 按影响选择验证

根据本次差异、直接消费者和共享依赖选择适用检查；适用项必须完成，工具或状态限制导致未完成时明确说明。检查通过后，仅在后续改动、失败或新发现的影响范围需要时补充或重复验证。

存档、背包、镜头、输入和场景流程按以下行为范围验证；多个范围受影响时合并覆盖：

- **改变存档数据或恢复逻辑**：必测新档写入及同场景读取、当前根格式下缺少组件记录或新增字段的恢复；存在完成态时验证回退后重新交互。手动和自动存档共用受影响实现时，两类入口都要覆盖。
- **影响场景定位、初始化／恢复时序、全局对象或场景间资源依赖**：补测跨场景读档及受影响的章节跳转。是否适用按共享依赖判断，不只看修改文件所在章节。
- **影响协程、演出、组件生命周期或输入锁**：覆盖正常结束、协程中断、禁用和读档打断时受影响的清理及输入释放路径。

进入 PlayMode 或运行测试前检查当前场景是否有未保存修改，记录本轮需要恢复的编辑器状态；会写盘时先保护用户存档和偏好。优先采用附加加载、临时场景副本或测试框架隔离，不能保存或丢弃用户未保存内容来方便测试。工具或状态限制某项必要验证时，完成其他独立检查并明确说明限制；不能把上一轮结果当成本轮重跑。

# 原项目双向合并执行流程

## 1. 保存、提交并固定输入

记录方向、原分支、待交付开发分支及作者、Git 状态、实际项目、Unity 会话和打开的场景。主程处理指定源分支时，原目录未提交内容属于当前检出分支，不能自动归入他人的交付。检查未完成 merge/rebase 和 worktree 占用。

通过连接到本项目的 Unity MCP 确认播放、编译、导入和未保存状态。播放中有需要保留的调整时先记录/保留，再停止播放，等待回到 Edit Mode，保存有效场景和资源。无法判断运行态修改归属时询问，不把退出播放后的默认值当作已保存。Editor 必须保持打开。

保存前识别实际脏场景和资源，仅保存确认需要保留的编辑；没有待保存内容时跳过，不把全局 SaveAssets 当作固定前置步骤。保存后核对 Git 差异，新增的无关材质写回不得自动纳入检查点。

审查暂存和未暂存差异，按授权范围创建本地检查点提交；无变化则跳过。排除项仍影响后续操作时先解决归属，不能丢弃、自动暂存进 stash 或强行切换。固定源 SHA；检查点提交失败就不继续合并。仅分析/先不提交的请求遵从其边界。

fetch 配置的 develop_base，固定远程 SHA，不能用陈旧本地引用冒充最新。读取 [场景配对与同步记录](scene-sync.md)，在切换前固定所有 A/S/T 输入及来源快照，包含直接修改基础场景和公共依赖的变化。Git blob 可直接读取，不复制整个项目。开始计时后复用同一任务记录。

**写入前检查点**：在第一次切分支、更新目标基线、Git 合并或场景写回之前，确认来源 snapshot 命令成功且文件可读取，快照的项目、分支、提交与已固定开发输入一致；各场景 A/S/T 的路径、GUID、commit/blob 及基准依据已记录，Editor 刷新/重载的控制与恢复方法可用。复用当前任务已有观察和快照，不为核对这些字段额外生成整组快照。缺项时先补齐，不进入写入阶段；若已发生写入，记录缺失及影响，不把合并后快照冒充合并前证据。deliver 更新目标基线后，再固定实际目标 T，保留原来源快照。

## 2. 原目录合并与 Editor 协调

按 [执行辅助工具](execution-tools.md) 保存必要的阶段续跑信息，并用 scene-guard-create/check 固定和核对既有目标场景保护。所有修改命令检查退出码；失败不执行后续写回、解锁或导入。工具不支持的新增/删除/移动场景继续按本流程处理，不把辅助工具的限制误当作允许遗漏这些变化。

修改工作树前，通过现有 Editor 能力记录并可靠暂停自动刷新及必要的程序集重载，确保没有播放、导入、编译或未保存编辑。仅暂停刷新不足以证明重载也被控制。不要临时注入会随切分支消失的 Assets 脚本作为唯一解锁手段；记录恢复方法，在异常和中断后也恢复本轮设置。能力不可用就停在写入前，不关闭 Editor 或新建工程绕过。

### develop_base → 当前开发分支（sync）

保持当前开发分支，合入固定远程 develop_base 提交。代码和公共资源按 Git 三方合并；场景只将主分支基础增量写入当前作者的个人场景，保留个人开发内容。当前分支基础场景及其他个人场景保留合入前字节和身份。输入 S 从固定远程提交读取，不能取当前分支仍保留旧内容的基础场景。该方向不移动本地 develop_base 引用。

### 当前开发分支 → develop_base（deliver）

在原目录切换到本地 develop_base；本地不存在时从已固定远程分支创建该标准分支。已有本地未推送提交必须保留：落后则快进，与远程分叉则正常合并并处理冲突，不 reset 到远程。目标分支被其他 worktree 占用时停止切换并说明，不擅自接管另一工作区。

固定更新后的本地目标 SHA，再合入之前固定的开发 SHA。场景只写对应基础场景，目标已有个人场景保留原状，目标不存在的个人场景不从开发分支新增。不是先把主分支合到开发分支再反向合回；也不依赖当前 HEAD 猜源版本。结果停留 develop_base，原开发分支保持检查点状态。

### 两个方向共同要求

开发内容合入目标时使用 git merge --no-ff --no-commit，防止快进或自动提交绕过场景写入控制；deliver 的目标远程对齐单独记录。保留正常 Git 历史，不整树 ours/theirs。Git already up to date 仍需检查两个不同场景文件之间未迁移的增量；必要时以普通提交记录场景迁移，不伪造 merge。

**场景写入控制**：合入前枚举双方及相关历史中的场景、配套 `.meta` 和重命名路径，固定接收分支起点的存在性及 blob，并生成本轮目标场景白名单。所有场景退出普通 Git 内容合并：在刷新和重载受控期间，Git 合并产生的场景结果只是临时状态；将这些精确路径的索引和工作树恢复到已固定接收起点，再仅将通过检查的三方候选写入白名单目标。接收起点不存在的非目标路径保持不存在；只处理本轮 Git 引入的路径，不删除未跟踪文件或用户并行编辑。目标自身也从合入前 T 构造候选，不能使用 Git 自动合并后的内容。此路径级处理是本流程的定向场景策略，不使用整树恢复、全局 merge=ours 配置或 reset/clean。

最终提交前同时核对索引和磁盘：白名单外的场景及 `.meta` 与接收起点完全一致，白名单内只含审核后的 R，且无未解决索引冲突。移动、删除、缺少配对或其他正式场景变化若无法纳入明确目标，列为待处理并暂停相关写入，不静默遗漏或扩大白名单。资源中对被保护场景的新增 GUID 引用也要核查；无有效目标时作为冲突处理。公共资源更新可能改变未写入场景的运行表现，“场景不变”指场景文件和身份不变。

先生成场景候选文件并完成结构/引用检查，再写回目标场景。候选文件是单文件证据，不是隔离 Unity 工程。冲突必须明确解决后才让 Unity 导入冲突资源；需等待用户裁决时保持刷新受控、记录恢复方法并说明暂停原因，不让 Editor 导入冲突标记。取消/退出任务前先协商保留或恢复现场，不能在冲突未清理时机械恢复刷新，也不能遗留未说明的工具锁。

稳定写入后恢复原刷新/重载设置，主动刷新并等待导入、编译完成；重新核对分支、HEAD、实际字节和 MCP 会话，重载目标场景。重载前再次确认没有用户在合并期间产生的新编辑，不把内存旧场景保存覆盖磁盘结果。保存、刷新、重载无法可靠完成时报告阻碍；禁止以关闭/重启 Editor 恢复。

### Reload 弹窗的人工接续

Unity 出现“场景已在磁盘上修改”的 Reload 弹窗时，由用户点击。确认弹窗内容、涉及场景以及合并前无未保存编辑后，提示用户点击 Reload 并回复；若存在新编辑或归属不明，先说明差异，不能让用户盲目重载。无需为这个弹窗启动截图故障排查或反复尝试自动点击。MCP 超时本身不证明存在弹窗：先结合导入日志或一次可用的窗口只读观察判断；无法确定时请用户确认 Unity 当前状态。

等待时保留本轮 task_id、分支/提交、证据目录、场景结果路径和锁状态，不继续场景写入、不反复轮询 MCP。用户确认后实测原项目与 Editor 会话、目标场景路径/GUID、无播放/编译/导入/未保存状态及本轮锁已解除，再从未完成阶段继续。会话或输入变化时只重新评估受影响证据；不得仅凭回复认定恢复成功，也不重做已完成的准备、合并、提交或已有有效验证。提交/推送前的远程新鲜度检查仍按第 5 节执行。

## 3. 场景三方增量与重复合并

按 [scene-sync.md](scene-sync.md) 逐对选择方向对应的基准。列出对象新增/删除、组件字段、Prefab override、Transform、内部/跨根/入向引用、资源 GUID 和 SaveId 差异。无变化快速路径必须基于输入内容和有效记录，不能仅看 Git 分支关系。

源侧独改应用；目标侧独改保留；双方同值视为对齐；同字段不同修改、删除与修改、父子重挂冲突按业务证据裁决，无法确定时提供具体两侧值和影响再询问。列表按稳定键匹配，不按索引硬合。fileID 稳定时可快速匹配；重编号时用稳定业务身份、组件及层级建立映射并重写全部相关引用。重名不唯一列冲突。

解析 Unity 文本保留数值字符串、packed array、!u! 类型和引用；不使用通用 YAML 自动数值转换重写整场景，不凭全局浮点容差忽略位置变化。文本无冲突不等于语义正确。二进制或不支持结构须使用 Editor 能力，不盲改。

保留目标场景自己的 .meta GUID：sync 保留个人身份，deliver 保留基础身份。烘焙数据不能跨身份直接套用；几何变化影响本轮必要烘焙时在当前目标场景重建并验证。不顺带删除个人副本、烘焙或静态标记。明确删除时检查引用并处理对应 .meta。

普通 Git 合并已经应用的 Prefab 和公共资源变化必须与场景迁移联合核对，避免重复应用。开发分支直接修改基础场景的增量单独固定来源和历史：sync 中基础文件仍受保护，确属本轮个人开发范围的增量三方纳入个人候选；deliver 中与个人增量逐项去重后纳入基础候选。同字段不同值必须裁决，不能整份旧基础覆盖目标，也不能在已同步的个人增量之外重复应用旧直接修改。每项记录已应用、已存在或明确排除；归属无法确定则暂停该项。历史排除项和冲突决定不能在反向同步时悄悄复活；双方继续修改时按新差异判断。

## 4. 按影响验证

**完整性**：本轮增量逐项为已应用、已存在、明确取消或冲突；目标独立改动保留，没有新增悬空引用、重复标识或遗漏依赖。区分历史缺引用与本轮问题，LFS 指针不当作资源实体。

**功能**：默认检查实际合入的变化及其依赖，不只检查冲突文件，也不默认全项目回归。局部机关验证相关场景和功能；公共存档、输入锁、全局 Prefab 等变化扩展到受影响旧功能。每组验证填写受影响功能、检查范围及选择理由。sync 使用结果个人场景，deliver 使用结果基础场景，不能用另一场景结果替代。

优先复用当前 Editor/MCP，遵守 [验证工具](automation-tools.md)。运行前检查光标、前台、渲染、输入保护帧等实际能力和前提；不满足时先诊断，不反复用相同错误环境重试。不得删断言凑通过。一次准备验证会话，串行运行所需检查并恢复场景、单例和输入状态，不另开 Editor。

保护用户存档和章节偏好；测试副本须实际验证不允许落盘。恢复仅处理确认属于本任务的副作用，不覆盖用户并行修改。共享材质写回不自动进入提交。

失败保留原始证据并区分业务、测试假设和环境问题。诊断使用独立 purpose=diagnostic 计划及检查，定位失败功能及直接依赖；修复后执行原 final 计划所需验证，未变化且已有有效结果的项不重复跑。修改输入使旧结果失效时重新验证，不能跨不相容快照拼通过。测试驱动入口不冒充完整玩家操作；人工未验单列。

## 5. 记录、提交、自动推送与结束

本轮 Docs/SceneHandoffs 目录保存一份合并报告和机器依据，复用已有同版本证据，不重复生成多份相同清单。包括方向、开发作者、固定提交、逐场景 A/S/T 与结果身份、冲突决定、直接基础修改、验证计划及结果、待人工确认项、最终文件哈希。同步记录遵循 scene-sync.md；原始失败保留，历史证据不重写。

使用标准 MCP 接入与 summarize 汇总测试数字，避免当轮专用校验脚本。计时区分保存/准备、合并、导入编译、测试、诊断、恢复和报告；区间包含等待时如实说明，不相加嵌套耗时，不承诺固定分钟数。

核对暂存范围，必要自动检查通过且未被要求等待时创建本地结果提交；人工待验状态明确保留，不能称全部验收通过。真实失败未解决时不进入正常完成提交/推送，除非用户明确接受具体范围。若用户要求人工通过后提交，保留现场且记录 pending，不能作为下一次成功基准。

必要验证通过、本地结果提交成功后，自动推送本次目标分支，不再询问是否推送：sync 推送当前开发分支，deliver 推送 develop_base。用户明确要求不推送或等待时停在指定阶段；仅维护技能、只读验收不触发推送。

推送远程优先遵从用户指定，否则核对目标分支的推送/上游配置；没有相关配置时，使用本轮已确认的 develop_base 远程，并推送同名目标分支。配置存在歧义或指向不同分支时先澄清，不猜测、不修改其他远程。使用显式目标 `git push <remote> HEAD:refs/heads/<目标分支>`，不依赖可能推送多个分支的默认设置，不顺带推送源分支或标签。

提交/推送前复查目标是否意外前移；推送前 fetch 并核对目标远程 SHA，若有本地尚未包含的远程提交，则正常合入并重验受影响范围，再推送，不强推。推送成功后读取目标远程引用，确认 SHA 与本地结果提交一致才报告已推送，并记录 push_verified。权限、网络或分支保护导致失败时保留本地提交并报告具体原因，不绕过限制；远程持续前移时停止重复尝试并说明尚未完成。

源检查点、Git 合并和场景迁移均无新增变化时跳过空提交；仍检查目标远程是否已包含本次结果，未包含则按上述规则推送，完全对齐则说明无需推送。

最终保留 Unity 打开、停止播放、工具锁定设置恢复，重载目标场景供人工测试。sync 停留开发分支，deliver 停留 develop_base。原项目不 detach、不执行隔离工作区释放、不删除 Library。报告提交、推送、自动验证和人工验证各自状态及实际路径。
